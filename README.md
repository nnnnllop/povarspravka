# Поварская справка (PovarSpravka)

**«Поварская справка» (v1.1)** — офлайн-приложение на Flutter (Android) для технологов общественного питания, поваров, диетологов и студентов кулинарных направлений. 

Приложение работает **100% офлайн** и рассчитывает химический состав, потери при кулинарной обработке и энергетическую ценность блюд с экспортом в готовые бланки (PDF, Word DOCX, Excel XLSX), идентичные стандартным бланкам технологических расчетов.

---

## Ключевые возможности

1. **Единая офлайн-база на 8 261 продукт** (32 группы: 12 таблиц Скурихина + 20 категорий BLS 4.0):
   - **Справочник И. М. Скурихина и В. А. Тутельяна (2002 г.)** — 1 108 базовых продуктов и полуфабрикатов (наивысший приоритет в поиске) + 13 дополнительных ингредиентов (`supplement`).
   - **BLS 4.0 (Bundeslebensmittelschlüssel)** — 7 140 продуктов с профессиональным переводом на кулинарный русский язык (*пахта, батат, фарш, потроха, творог*).
   - Мгновенный полнотекстовый поиск **SQLite FTS5** (< 15–20 мс, замер — медиана 1,09 мс / p95 12,34 мс на 101 запрос) с поиском по префиксам, синонимам и фильтрацией по категориям.

2. **Неограниченное число ингредиентов**:
   - Нет лимита на 10 строк: можно составлять рецепты из 15, 20, 50+ компонентов.
   - Плавный виртуализированный список с изменением порядка (drag & drop), свайпом для удаления и быстрой правкой граммовок.

3. **Тактильный ввод и учет мер**:
   - Быстрые чипсы граммовки (`+10г`, `+50г`, `+100г`, `+250г`).
   - Порционные меры из справочника (штуки, столовые ложки, стаканы).
   - Автоматический учет отходов холодной обработки (брутто -> нетто).

4. **Расчёт нутриентов после тепловой обработки**:
   - Потери берутся из таблицы «группа продукта × способ обработки» (14 групп, способы: без обработки, варка, тушение, жарка, запекание, на пару, бульон) и применяются к каждому ингредиенту:
     $$Б_{\text{гот}} = \sum_i Б_i \times \frac{100 - \text{потери}_Б(\text{группа}_i, \text{способ})}{100}$$
     Жиры и углеводы — так же. Источники каждой ячейки и список неподтверждённых (UNVERIFIED) — в [`docs/COEFFICIENT_SOURCES.md`](docs/COEFFICIENT_SOURCES.md).
   - Группу продукта определяет классификатор; повар может задать группу и способ обработки отдельного ингредиента вручную.
   - Энергетическая ценность (ЭЦ) рассчитывается по классической формуле:
     $$\text{ЭЦ} = Б_{\text{после т.о.}} \times 4 + Ж_{\text{после т.о.}} \times 9 + У_{\text{после т.о.}} \times 4$$
   - Вес готового блюда вводит повар (приложение его не угадывает). Без веса итог даётся на всё блюдо, «в 100 г» — прочерк.
   - Новое блюдо — «без обработки». Старый расчёт (сохранность 94 / 88 / 91 % на всё блюдо) остаётся способом «старый расчёт»; сохранённые ранее документы открываются с прежними числами.
   - На экране и в бланках нового расчёта — пометка «Пищевая ценность рассчитана по открытым справочным коэффициентам потерь, не по ГОСТ.»

5. **Два режима формирования бланка**:
   - **«Бланк с крестом (учебный)»**: диагональный крест/прочерк в колонке ккал для строк сырья; калорийность вычисляется исключительно на строке *«После тепловой обработки»*.
   - **«Подробный расчёт»**: калорийность рассчитывается для каждого сырого ингредиента, суммируется в *«ИТОГО»*, затем пересчитывается с учётом потерь при тепловой обработке.

6. **Экспорт без интернета и без платных библиотек**:
   - **PDF 1:1 к фото**: векторная таблица с рамками, двухуровневой шапкой, диагональными крестами, формульным подвалом и автоматической разбивкой на страницы при $> 18$ строк.
   - **DOCX**: нативный файл Microsoft Word с редактируемой таблицей.
   - **XLSX**: электронная таблица Microsoft Excel с числовыми ячейками для дальнейшей аналитики.
   - Прямая печать через системный сервис печати Android.

7. **Минималистичный монохромный интерфейс (v1.1)**:
   - Светлая и тёмная темы в сдержанной монохромной палитре с табличными шрифтами и чёткими границами карточек и нижних панелей.
   - Фокус на расчёте блюд («Новый расчёт» / «Продолжить расчёт») и «Справочнике» продуктов — без лишних разделов, плавающих кнопок (FAB) и визуального шума.
   - Спокойная адаптивная вёрстка (`AppContentFrame` до `640 dp`) для узких смартфонов, альбомной ориентации и широких экранов; единая шкала кнопок и клавиш нумпада от `48 dp` по высоте нажатия, выровненные парные кнопки и поддержка масштабирования системного шрифта.

## Прозрачный расчёт и вес готового блюда

- Вес готового блюда вводит повар; на нутриенты вес не влияет, он нужен для пересчёта «на 100 г» и порции. Модель уварки/выхода удалена.
- Без веса итог показывается на всё блюдо, строки «в 100 г» — прочерком (экран, PDF, DOCX, XLSX).
- Карточка ингредиента показывает потери: «Потери: группа · способ — Б x %, Ж y %, У z %»; «(вручную)» — задано поваром, «(оценка)» — значение из списка UNVERIFIED.
- Инспектор и справка «Как считается» показывают потери, округление, формулу 4Б + 9Ж + 4У и нормализацию на 100 г.
- Если последнее автосохранение повреждено, приложение восстанавливает резервную копию и сообщает об этом баннером.
- Коэффициенты потерь взяты из открытых источников (`docs/COEFFICIENT_SOURCES.md`), не из текста ГОСТ.

## Сборка и запуск

### Требования
- Flutter SDK 3.19+ / Dart 3.3+
- JDK 17; Android SDK Platform 34 и Build Tools для сборки (минимальная версия устройства: API 24 / Android 7.0+)
- Gradle Wrapper 8.4 включён в `app/android/`
- Android NDK 28.2.13676358 (используется уже установленная версия; плагины требуют не ниже 25.1.8937393). Модуль printing компилируется с API 34, как и приложение.

### Запуск в режиме разработки:
```bash
cd app
flutter pub get
flutter run
```

### Сборка релизного APK:
```bash
cd app
flutter build apk --release
```
Готовый установочный APK файл будет расположен в:
`app/build/app/outputs/flutter-apk/app-release.apk`

### Подпись APK
Релизный APK подписан производственным сертификатом `CN=PovarSpravka, OU=Culinary Tech, O=PovarSpravka, L=Moscow, ST=Moscow, C=RU` по схеме APK Signature Scheme v2.
Для сборки релизного APK используется конфигурация `app/android/key.properties` (см. шаблон `app/android/key.properties.example` и подробную инструкцию в [SIGNING.md](SIGNING.md)). В `build.gradle` настроена строгая проверка: сборка в режиме release завершается с ошибкой (`GradleException`) при отсутствии производственных ключей (тихий fallback на debug-подпись исключен).

Приложение работает 100% автономно и офлайн:
