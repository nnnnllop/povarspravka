## Порядок запуска

```powershell
# Из корня репозитория
cd tools/data_pipeline/bls_v4
$env:PYTHONIOENCODING='utf-8'
$env:RIVER_API_KEY='<ваш ключ api.river.ai>'
python download_bls.py     # скачать и распаковать архив (идемпотентно)
python translate_bls.py    # DE/EN -> RU, пакеты по 44, 8 потоков, кэш JSONL
python assemble_bls.py     # bls_products.json
python validate_bls.py     # приёмка -> validation_report.json
```

## Модули

- `download_bls.py` — загрузка архива с `blsdb.de`, распаковка в
  `data/bls_v4/raw/`, поиск книги данных. Повторный запуск ничего не качает
  (`--force` — перекачать).
- `mapping.py` — соответствие «код столбца BLS → ключ единого формата,
  единица, подпись» и детерминированное отображение категорий по первой
  букве кода.
- `translate_bls.py` — кулинарный перевод названий через `api.river.ai`
  (модель `deepseek-ai/DeepSeek-V4.1-Flash-1017`). На входе
  `code / name_de / name_en / category`, на выходе строгий JSON-массив
  `[{bls_code, name_ru, synonyms_ru}]`; каждый ответ дописывается в
  `translations_cache.jsonl`, поэтому запуск можно прерывать.
- `assemble_bls.py` — сборка `bls_products.json`. В книге каждый показатель
  занимает три столбца подряд (`Wert`, `Datenherkunft`, `Referenz`), поэтому
  значение берётся из **первого** столбца с кодом показателя, а не из `dict`
  по первому слову шапки.
- `validate_bls.py` — проверки и отчёт.

## На что обращать внимание

- Пропуски BLS закодированы строками `-`, `<LOD`, `TR`, `<LOQ` — все они
  превращаются в «нет значения», а не в ноль.
- Для чистой воды BLS публикует 100,585 г воды на 100 г — это округление,
  а не ошибка; такие значения вынесены в предупреждения
  `rounding_over_100`, а не в ошибки.
- Формула ЭЦ BLS: `4·белки + 9·жиры + 4·усвояемые углеводы + 2·ПВ +
  7·алкоголь + 3·кислоты + 2,4·полиолы`.
- `name` = русский перевод, `name_de`/`name_en` сохранены, `synonyms` —
  бытовые синонимы для поиска.
