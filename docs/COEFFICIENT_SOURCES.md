# Источники коэффициентов потерь при тепловой обработке

Задача 2026-11-03 «Упрощение расчёта — только нутриенты после тепловой обработки».
Код: `app/lib/core/calculation/loss_table.dart` (`LossTable`, `NutrientLoss`, `LossSource`).
Этот документ — источник правды для значений: машиночитаемый блок в конце
файла сверяется с кодом тестом `app/test/loss_table_test.dart` и используется
независимым эталоном `app/test/fixtures/nutrients_benchmark_reference.py`.

> Пищевая ценность рассчитана по открытым справочным коэффициентам потерь, не по ГОСТ.
> (`kNotGostNotice` — печатается на экране, в бланках PDF/DOCX/XLSX и в справке.)

## 1. Модель расчёта

```
Б_готов = Σ Б_i × (100 − потериБ(группа_i, способ_i)) / 100
Ж_готов = Σ Ж_i × (100 − потериЖ(группа_i, способ_i)) / 100
У_готов = Σ У_i × (100 − потериУ(группа_i, способ_i)) / 100
ккал    = 4 × Б_готов + 9 × Ж_готов + 4 × У_готов
```

* `Б_i`, `Ж_i`, `У_i` — нутриенты ингредиента в сырье: масса нетто × содержание
  на 100 г / 100 (брутто → нетто по проценту отходов справочника — не менялось).
* `группа_i` — одна из 14 групп (`LossGroup`); по умолчанию определяется
  классификатором `FoodClassifier` по группе и названию продукта справочника,
  повар может сменить её у ингредиента.
* `способ_i` — способ блюда (`Dish.process`) или собственный способ ингредиента
  (например, лук обжарен для супа). Готовое блюдо справочника (`is_dish = 1`)
  повторных потерь не получает (`cold`), если повар не указал способ явно.
* Округление: Б/Ж/У каждой строки — HALF-UP до 0,01 г в десятичной арифметике;
  итог — сумма строк; ккал — от итоговых Б/Ж/У, HALF-UP до 0,1.
* Масса готового блюда НЕ моделируется (развариваемость, уварка, экстракция
  удалены вместе с `yield_physics.dart`): её вводит повар. Нет веса — итог на всё
  блюдо, «на 100 г» не считается.
* `cold` (без обработки) — потерь нет (0 / 0 / 0, S4). Новое блюдо — `cold`.
* `legacy` (старый расчёт) — тройка блюда 0,94 / 0,88 / 0,91 к суммам сырья,
  выход — введённый или сумма нетто. Так считаются документы без ключа `process`
  (созданные до 2026-11-03) — они дают прежние числа. Таблица ниже для `legacy`
  не применяется.

## 3. Правила переноса источника в таблицу

1. Углеводы: для круп, бобовых, корнеплодов и картофеля, муки и хлеба — столбец
   «крахмал» прил. 4; для овощей, фруктов, сахара — «моно- и дисахариды».
2. Прочерк «–» в источнике = 0 % потерь (S4).
3. Варка растительных — строка «без слива отвара» (жидкость остаётся в блюде или
   впитывается). Строка «со сливом» используется только для баланса бульона.
4. Нет строки в источнике → ближайший аналог прил. 4 или обобщённые потери прил. 5.
   Такие ячейки помечены в коде `// UNVERIFIED` и `NutrientLoss.unverified`
   (в UI и отчётах — «значение не подтверждено источником»).
5. Бульон (`stock`): считаются нутриенты, ПЕРЕШЕДШИЕ в бульон. Мясо, кости, овощи
   извлекаются, поэтому «потеря» = 100 % − доля, перешедшая в воду; доля — баланс
   масс по прил. 4 (что продукт теряет при варке, то переходит в бульон). Продукты,
   не отделяемые от жидкости (молоко, жир, сахар, мука, соль), остаются в бульоне
   и считаются как при варке. Весь столбец — UNVERIFIED.
6. Жарка, жиры и масла: S3 даёт только жир (50 %); те же 50 % для Б и У
   приняты по аналогии — UNVERIFIED.
7. Строки «котлеты» и «пассерование» прил. 4 не используются: таких способов нет в
   перечне приложения.

(BLS, открыт только на чтение). Вес готового блюда для проверки — по балансу воды:
`масса_сырья × (100 − вода_сырого) / (100 − вода_готового)`. Расчёт модели делают и движок
приложения, и независимый эталон `app/test/fixtures/nutrients_benchmark_reference.py`
(Decimal, округление HALF-UP); тест `app/test/nutrients_benchmark_test.dart` требует
отклонения не более ±10 % ккал на 100 г.
